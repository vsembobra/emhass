# EMHASS Shadow — теневой план батареи

Аддон каждый день считает, **как было бы лучше** управлять батареей, и показывает
это в панели и уведомлении. По умолчанию в инвертор он **ничего не записывает** —
это безопасный теневой режим: вы наблюдаете за качеством прогнозов и советов
столько, сколько нужно. Когда будете готовы, переключатель «Применять план
к инвертору» в настройках включает запись целевых SOC в зоны TOU.

## Установка

**Через локальную папку (без GitHub):**

1. Соберите архив: `./make_dist.sh` (в репозитории) или получите готовый
   `emhass-shadow-<версия>.tar.gz`.
2. Распакуйте и скопируйте папку `emhass_shadow` в `/addons/` на хосте
   Home Assistant OS — через аддон Samba (сетевой диск `\\<ha>\addons`) или
   SSH.
3. Настройки → Дополнения → Магазин дополнений → меню ⋮ → «Проверить
   наличие обновлений» → аддон появится в разделе «Локальные дополнения» →
   Установить. Сборка образа занимает 10–20 минут.
4. Настройте параметры (вкладка «Конфигурация») и нажмите «Запустить».

**Через GitHub:** опубликуйте содержимое архива как репозиторий и добавьте
его URL в Магазин дополнений → ⋮ → «Репозитории».

Первый план появится сразу (на упрощённом прогнозе); собственные модели
прогноза обучатся автоматически, когда накопится несколько дней истории.

## Что делает

- Собирает почасовую историю из Home Assistant (нагрузка, солнце, батарея, сеть)
  и ведёт журнал отключений электричества.
- Строит прогноз нагрузки и солнечной генерации на 24 часа вперёд с коридором
  неопределённости (P10 / P50 / P90, модели LightGBM).
- Учится на данных именно вашего объекта: модели автоматически переобучаются
  с заданным интервалом (можно выключить в настройках).
- Считает резерв на случай отключения сети: по статистике прошлых отключений,
  с повышением в часы, когда отключения случались чаще.
- MILP-оптимизатор (CVXPY/HiGHS) строит оптимальный суточный план
  заряда/разряда: учитывает дешёвые тарифные окна (ночная зарядка из сети),
  КПД батареи, ограничения мощности инвертора и плавающий пол SOC.
- Выводит целевые SOC для шести зон TOU инвертора — видно, что бы поменял
  оптимизатор и на сколько.
- Показывает точность вчерашних прогнозов, суточную статистику энергии и
  оценку потерь от усечения солнца (когда батарея полна и продажи в сеть нет).

## Требования

Интеграция вашего инвертора должна давать в Home Assistant сенсоры
(значения по умолчанию — для Deye, все имена меняются в настройках):

| Данные | Сущность по умолчанию |
| --- | --- |
| Мощность нагрузки, Вт | `sensor.inverter_load_power` |
| Критическая (UPS) нагрузка, Вт | `sensor.inverter_load_ups_power` |
| Мощность солнечных панелей, Вт | `sensor.inverter_pv_power` |
| Мощность батареи, Вт | `sensor.inverter_battery_power` |
| Обмен с сетью, Вт | `sensor.inverter_grid_power` |
| Заряд батареи, % | `sensor.inverter_battery` |
| Статус сети | `binary_sensor.inverter_grid` |
| Напряжение фаз L1–L3, В | `sensor.inverter_grid_l1_voltage` и т.д. |
| Счётчик отдачи в сеть, кВт·ч | `sensor.inverter_total_energy_export` |
| Уличная температура, °C | `sensor.home_temperature` |
| SOC зон TOU (шаблон, 1–6) | `number.inverter_program_{n}_soc` |
| Время старта зон TOU (шаблон) | `time.inverter_program_{n}_time` |

Плюс один `input_number` с текущим нижним порогом SOC инвертора (в процентах) —
с ним панель показывает, на сколько рекомендация отличается от действующей
настройки.

Для прогноза погоды нужен доступ в интернет (Open-Meteo, без ключей). Без
интернета аддон использует последний сохранённый прогноз и честно помечает
это в отчёте.

## Настройка

Все параметры — на странице конфигурации аддона, у каждого есть подсказка.
Минимум для старта:

1. Координаты и часовой пояс объекта.
2. Ёмкость батареи, границы SOC, КПД, лимиты мощности инвертора.
3. Если имена сущностей отличаются — поправьте карту сущностей.
4. Если ночью электричество дешевле — включите «Ночной дешёвый тариф»,
   укажите цены и окна (`23:00-07:00`, можно несколько через запятую).

Первый расчёт выполняется в заданное время (`run_time`) или по кнопке
«Пересчитать сейчас» в панели. Панель открывается из бокового меню
Home Assistant — «Теневой план».

## Как читать панель

- **Рекомендуемый пол SOC** — какой нижний порог батареи советует планировщик
  на ближайший час, и на сколько он отличается от текущего в инверторе.
- **Пол SOC по часам** — плавающий профиль на сутки: ночью выше (солнца нет),
  днём ниже (солнце подзарядит).
- **Оптимальный план (MILP)** — траектория заряда батареи по часам от
  оптимизатора, стоимость дня и экономия против режима «без батареи».
- **Зоны TOU** — текущие настройки шести программ инвертора и что советуют
  эвристика и оптимизатор.
- **Суточные данные** — потребление, солнце, потери усечения, работа батареи,
  импорт из сети за каждый из последних 14 дней.
- **Точность прогнозов** — насколько вчерашний прогноз совпал с фактом.

## Режимы: советовать или применять

По умолчанию аддон работает в **теневом режиме**: только читает историю и
состояния сенсоров, а результат показывает в панели и уведомлении. В
инвертор не отправляется ничего.

Когда убедитесь, что прогнозы точные, а советы разумные (обычно 1–2 недели
наблюдений), включите в настройках **«Применять план к инвертору»**. Тогда
после каждого расчёта аддон записывает через Home Assistant:

- целевые SOC шести зон TOU (из MILP-оптимизатора, а если он недоступен —
  из эвристики плавающего пола);
- нижний порог SOC в указанный `input_number`.

Записываются только изменения от 5 процентных пунктов — лишних записей в
инвертор не будет. Каждая запись перечисляется в уведомлении и в отчёте,
ошибки записи помечаются отдельно.

## Безопасность

В теневом режиме единственная запись в Home Assistant — сервисное
уведомление с итогом расчёта. В режиме применения добавляются записи
`number.set_value` / `input_number.set_value` по сущностям из карты — иных
обращений к инвертору нет, и все они ограничены настроенными границами SOC.
