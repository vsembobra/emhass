# EMHASS Shadow — теневой план батареи

Аддон каждый день считает, **как было бы лучше** управлять батареей, и показывает
это в панели и уведомлении. По умолчанию в инвертор он **ничего не записывает** —
это безопасный теневой режим: вы наблюдаете за качеством прогнозов и советов
столько, сколько нужно. Когда будете готовы, переключатель «Применять план
к инвертору» в настройках включает запись целевых SOC в зоны TOU.

## Установка

**Через локальную папку (без GitHub):**

1. Соберите архив: `./make_dist.sh` (в репозитории) или получите готовый
   `emhass-shadow-<версия>.tar.gz`.
2. Распакуйте и скопируйте папку `emhass_shadow` в `/addons/` на хосте
   Home Assistant OS — через аддон Samba (сетевой диск `\\<ha>\addons`) или
   SSH.
3. Настройки → Дополнения → Магазин дополнений → меню ⋮ → «Проверить
   наличие обновлений» → аддон появится в разделе «Локальные дополнения» →
   Установить. Сборка образа занимает 10–20 минут.
4. Настройте параметры (вкладка «Конфигурация») и нажмите «Запустить».

**Через GitHub (рекомендуется):**

1. Магазин дополнений → меню ⋮ → «Репозитории» → добавьте
   `https://github.com/vsembobra/emhass`.
2. В магазине появится «EMHASS Shadow» → Установить. Сборка образа при
   первой установке занимает 10–20 минут.
3. Настройте параметры (вкладка «Конфигурация») и нажмите «Запустить».

При первом запуске аддон сам забирает из Home Assistant всё, что там уже
есть: подробную историю recorder (`history_backfill_days`, обычно 10–14 дней),
журнал отключений за ту же глубину и почасовую долгосрочную статистику за
месяцы (`history_statistics_days`, по умолчанию год — для сенсоров со
`state_class`). Модели обучаются на этих данных сразу, и уже первый план
считается на прогнозах вашего дома. Для давно установленного аддона то же
делает кнопка «Загрузить историю» в панели.

## Что делает

- Собирает почасовую историю из Home Assistant (нагрузка, солнце, батарея, сеть)
  и ведёт журнал отключений электричества.
- Строит прогноз нагрузки и солнечной генерации на 24 часа вперёд с коридором
  неопределённости (P10 / P50 / P90, модели LightGBM).
- Учится на данных именно вашего объекта: модели автоматически переобучаются
  с заданным интервалом (можно выключить в настройках).
- Держит резерв на отключение только пока идёт серия отключений (см. ниже).
- MILP-оптимизатор (CVXPY/HiGHS) строит оптимальный план на 48 часов:
  ночная зарядка из сети — только если включён ночной тариф и это выгодно,
  к восходу батарея разряжается, чтобы принять солнце, КПД батареи и
  ограничения мощности инвертора учтены; жёсткий нижний порог — резерв.
- Выводит целевые SOC для шести зон TOU инвертора — видно, что бы поменял
  оптимизатор и на сколько.
- Показывает точность вчерашних прогнозов, суточную статистику энергии и
  оценку потерь от усечения солнца (когда батарея полна и продажи в сеть нет).

## Требования

Интеграция вашего инвертора должна давать в Home Assistant сенсоры
(значения по умолчанию — для Deye, все имена меняются в настройках):

| Данные | Сущность по умолчанию |
| --- | --- |
| Мощность нагрузки, Вт | `sensor.inverter_load_power` |
| Критическая (UPS) нагрузка, Вт | `sensor.inverter_load_ups_power` |
| Мощность солнечных панелей, Вт | `sensor.inverter_pv_power` |
| Мощность батареи, Вт | `sensor.inverter_battery_power` |
| Обмен с сетью, Вт | `sensor.inverter_grid_power` |
| Заряд батареи, % | `sensor.inverter_battery` |
| Статус сети | `binary_sensor.inverter_grid` |
| Напряжение сети (любая фаза), В — необязательно | `sensor.inverter_grid_l1_voltage` |
| Счётчик отдачи в сеть, кВт·ч | `sensor.inverter_total_energy_export` |
| Уличная температура, °C | `sensor.home_temperature` |
| SOC зон TOU (шаблон, 1–6) | `number.inverter_program_{n}_soc` |
| Время старта зон TOU (шаблон) | `time.inverter_program_{n}_time` |

Плюс один `input_number` с текущим нижним порогом SOC инвертора (в процентах) —
с ним панель показывает, на сколько рекомендация отличается от действующей
настройки.

Для прогноза погоды нужен доступ в интернет (Open-Meteo, без ключей). Без
интернета аддон использует последний сохранённый прогноз и честно помечает
это в отчёте.

## Настройка

Все параметры — на странице конфигурации аддона, у каждого есть подсказка.
Минимум для старта:

1. Координаты и часовой пояс объекта.
2. Ёмкость батареи, границы SOC, КПД, лимиты мощности инвертора.
3. Если имена сущностей отличаются — поправьте карту сущностей.
4. Если ночью электричество дешевле — включите «Ночной дешёвый тариф»,
   укажите цены и окна (`23:00-07:00`, можно несколько через запятую).

Первый расчёт выполняется в заданное время (`run_time`) или по кнопке
«Пересчитать сейчас» в панели. Панель открывается из бокового меню
Home Assistant — «Теневой план».

## Как читать панель

- **Рекомендуемый пол SOC** — какой нижний порог батареи советует планировщик
  на ближайший час, и на сколько он отличается от текущего в инверторе.
- **Пол SOC по часам** — плавающий профиль на сутки: ночью выше (солнца нет),
  днём ниже (солнце подзарядит).
- **Оптимальный план (MILP)** — траектория заряда батареи по часам от
  оптимизатора, стоимость дня и экономия против режима «без батареи».
- **Зоны TOU** — текущие настройки программ инвертора и что советуют
  эвристика и оптимизатор.
- **Самообучение и автонастройка** — поправка прогнозов, дрейф моделей,
  выученные параметры железа, итоги подбора на истории, окна переносимых
  нагрузок и флаги заряда из сети по зонам.
- **Суточные данные** — потребление, солнце, потери усечения, работа батареи,
  импорт из сети за каждый из последних 14 дней.
- **Точность прогнозов** — насколько вчерашний прогноз совпал с фактом.

## Самообучение: как аддон подстраивается под объект

Аддон учится на данных именно вашего дома и с каждым днём работает точнее:

- **Ежедневная поправка прогнозов.** Каждый выданный прогноз пишется в
  журнал (`/data/forecast_log.jsonl`). По парам «прогноз — факт» за две
  недели P50 нагрузки сдвигается по часам суток, P50 солнца масштабируется,
  а коридор P10–P90 расширяется или сужается так, чтобы в него попадало
  около 80 % фактов. Это работает каждый день, не дожидаясь переобучения.
  Поправка привязана к версии модели: после обновления модели она
  набирается заново по прогнозам новой модели, а не наследует старую.
- **Дрейф.** Если за неделю прогноз систематически смещён больше чем на 25 %
  или охват коридора упал ниже 60 %, модели переобучаются раньше срока.
- **Переобучение «новая против текущей».** Новая модель сравнивается с
  работающей на свежих днях, которых не видела ни одна из них, по тому же
  пути, что и в ежедневном плане, и встаёт на место только если не хуже.
  Затем она дообучается на всей истории; свежие данные весят больше
  (период полураспада 60 дней), так что модель следует за изменениями в доме.
- **Модель нагрузки** учитывает прогноз температуры, горизонт прогноза
  (1–24 ч), часовой пояс объекта и ваши праздники (`load_holidays`).
- **Железо по данным** (раз в неделю): реальная ёмкость и КПД батареи по
  глубоким циклам, наблюдаемая мощность заряда и разряда (в том числе
  снижение тока у полной батареи), ориентация и мощность панелей по ясным
  дням, профиль критической нагрузки по часам.
- **Подбор запаса на истории** (раз в сутки): последние две недели
  проигрываются в симуляторе батареи с реальными резервами, солнцем,
  нагрузкой, тарифом и отключениями для каждого допустимого запаса сверх
  резерва (+0/+1/+2 ч критической нагрузки). Сравнение идёт в порядке
  приоритетов: недоданная критическая энергия, затем усечённое солнце, затем
  стоимость — меньший запас, который оставил бы резервную линию без света,
  всегда проигрывает.
- **План vs факт.** Каждый прошедший день пересчитывается с фактической
  нагрузкой и солнцем; расхождение импорта делится на «из-за прогноза» и
  «из-за исполнения» (инвертор не выполнил план).

Выученное по умолчанию только показывается. Переключатель **«Автонастройка
по данным»** (`autotune`) применяет его: ёмкость и КПД — только если оценка
прошла все проверки, лимиты мощности — только в сторону повышения, запас
сверх резерва — только из тех, что разрешает приоритет.

## Отключения: серия или тишина

Отключения идут сериями: если начали отключать, отключают и дальше, а две
недели тишины значат, что серия закончилась. Аддон защищается только от
отключений идущей серии и не держит запас под «фантомные»:

- **Серия идёт** (последнее отключение было не больше `outage_memory_days`
  назад, по умолчанию 14): резерв = критическая нагрузка × длительность
  отключений этой серии (P90; P95 в режиме надёжности, P80 в экономии),
  выше в те часы, когда серия отключала, плюс запас сверх резерва. Первое
  же отключение после тишины включает этот режим. После возврата сети
  резерв восстанавливается из сети при любом тарифе.
- **Тишина**: резерв под отключения не держится, жёстко только min SOC (и
  минимальная автономия, если вы её задали).

Сколько энергии держать на вечер и ночь сверх резерва, решает оптимизатор
по прогнозу и цене. При одинаковой цене весь день аддон не заряжает батарею
из сети вовсе (кроме восстановления резерва во время серии): цикл заряд-
разряд теряет около 10 % и ничего не даёт.

## Что задаёт пользователь

- **Приоритет** (`priority_mode`): `resilience` — максимум надёжности,
  `balanced` — как раньше, `economy` — больше солнца и экономии. Определяет
  квантиль длительности отключений (95/90/80 %) и границы автонастройки.
- **Минимальная автономия** (`reserve_cold_start_hours`, по умолчанию 0) —
  сколько часов критической нагрузки держать даже без отключений.
- **Память серии отключений** (`outage_memory_days`, по умолчанию 14).
- **Переносимые нагрузки** (`deferrable_loads`) — бойлер, стиралка, насос:
  мощность, сколько часов работать и в каком окне. Аддон подберёт время на
  солнце, которое иначе ушло бы в усечение, и покажет его в панели,
  уведомлении и (с `publish_sensors`) в сенсоре для вашей автоматизации.

## Совместимость с инверторами

Аддон управляет инверторами с программами по времени (TOU): у каждой зоны
есть время старта и Batt% — одновременно нижний порог разряда и цель заряда
из сети. По умолчанию — Deye (6 зон, шаг 5 %). Для другого TOU-инвертора
задайте шаблоны сущностей, `tou_zones` и `tou_soc_step_pct`. Если указать
`tou_grid_charge_entity_template` (switch или input_boolean с `{n}`), аддон
в режиме применения сам включает заряд из сети только там, где он нужен для
резерва, в дешёвые часы, а без тарифа — в зонах без солнца. Инверторы,
которыми управляют уставкой мощности (например Victron ESS), этим аддоном
не поддерживаются.

## Режимы: советовать или применять

По умолчанию аддон работает в **теневом режиме**: только читает историю и
состояния сенсоров, а результат показывает в панели и уведомлении. В
инвертор не отправляется ничего.

Когда убедитесь, что прогнозы точные, а советы разумные (обычно 1–2 недели
наблюдений), включите в настройках **«Применять план к инвертору»**. Тогда
после каждого расчёта аддон записывает через Home Assistant:

- целевые SOC зон TOU (из MILP-оптимизатора, а если он недоступен — из
  эвристики плавающего пола); каждая зона держит не меньше самого высокого
  резерва отключений внутри своего окна;
- нижний порог SOC в указанный `input_number`;
- флаги заряда из сети по зонам, если задан их шаблон.

Записываются только изменения не меньше шага SOC инвертора — лишних записей
в инвертор не будет. Каждая запись перечисляется в уведомлении и в отчёте,
ошибки записи помечаются отдельно.

## Безопасность

В теневом режиме единственная запись в Home Assistant — сервисное
уведомление с итогом расчёта. В режиме применения добавляются записи
`number.set_value` / `input_number.set_value` по сущностям из карты и, если
задан шаблон флагов заряда из сети, `switch.turn_on/turn_off`
(`input_boolean.*`) по этим сущностям — иных обращений к инвертору нет, и
все записи SOC ограничены настроенными границами. Переключатель
«Публиковать сенсоры» создаёт в Home Assistant состояния
`sensor.emhass_shadow_*` (это не запись в инвертор). Сами переносимые
нагрузки аддон никогда не включает.
